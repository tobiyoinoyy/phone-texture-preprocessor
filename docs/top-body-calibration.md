# 顶面本体标定与独立运行

适用范围：当前命名、方向、分辨率和拍摄姿态符合 iPhone 17 铝材质检采集规范的六面原图。程序不调用 LLM、Agent 或生图服务；BiRefNet_dynamic 是可由程序直接调用的分割模型，并不等于 Agent 依赖。输入六张原图即可调用 `phone-texture auto`。最终用户验收不参与算法执行。

## 必须满足的结果

- top 只保留真实顶边框；整块相机台阶、镜头圆柱、镜片及凸起轮廓均排除。只去镜头圆柱仍不合格。
- 相机不参与顶面上缘、角度、厚度、尺寸标定。每张重新测量自己的原图；运行不读历史 SKU 坐标或验收蒙版。
- 两端圆角、边框内部纹理和真实损伤保留；仅修改透明度并做一次刚性旋转，不画出原图没有的轮廓。
- 原图证据不足时失败，错误码以 `TOP_` 开头；无 Agent 补点重试、无阈值放宽、无静默保留摄像头。

## 程序实现与拒绝条件

`phone_texture/top_frame.py` 从主连通体两端露出的圆角测量上下边界。拟合点位于本采集规范的外侧 0.6%–3.5% 宽度范围，内部交错留出 1/3 样点检查拟合；这些是统一采集规范，不是逐 SKU 标定。拟合残差 p95 ≤1.5 px，留出误差 p95 ≤2 px，刚性旋转后两条边剩余倾斜 ≤0.15°（厚度差记录为像素值，不再使用旧的固定 4 px 限制）。角点形状/尺度及原图 RGB 梯度也必须符合规范。中央两半的原图交界各需至少 80% 支持。该有限模型不声称识别任意型号、透视、遮挡或拍摄方式；不支持时返回失败。

### 2026-11-18：可见下边缘兜底

仅当原圆角拟合或上下导轨一致性失败时，尝试直接测量两端 5%–12%、88%–95% 的可见下边缘，避免用极短圆角外推整条直边。每端仍按 2/3 拟合、1/3 留出，分别检查原有 1.5 px / 2 px 残差；64、128、192 三档透明度的端点差必须 ≤1.5 px。两端原图 RGB 边缘各至少 80% 支持，独立 RGB 拟合残差及其与透明度边界的差均 ≤2 px。圆角不得突出下边缘，圆角 RGB 支持仍需 ≥80%。

上边缘仍只由原来的两端机身圆角确定；相机台阶不参与拟合。上下导轨 ≤0.15°、相机排除、机身保留、旋转及精裁门禁全部照旧。兜底不重建圆角、不修改 RGB；原规则已通过的输入不走新分支，报告与输出保持不变。记录 `original_failure` 和 `top_body_corners_and_exposed_lower_v2`，失败时保留原错误及兜底拒绝原因。回归见 `tests/test_top_exposed_lower.py`。

相机上边界的广泛支持不能替代机身证据。源图本体内部像素逐像素验证，外部相机区域 alpha 必须为零，旋转及透明精裁后再次检查。运行报告包含采样点、残差、RGB 支持率、变换检查、源图/输出哈希和 `runtime_agent_required: false`。代码通过不等于未知照片均正确，实际样本回归另存。

`auto` 和 `standardize` 的 top 共用标定。旧 `geometry-guides` 的 top 必须提供原图并通过同样的相机排除和机身保留检查；`reviewed` 不能豁免。低层仅有 matte 的 `extract_frame_strip(face='top')` 拒绝处理，使用带 `source_image` 的 `normalize_frame_strip`。已裁 PNG 的 `deskew` 仅处理方向，不能证明摄像头已去除；它不替代原图标定。

## 自动运行与验收的边界

`auto` 内部的六面处理、蒙版、光照参数、背面天线基准和数值检查都是软件逻辑，开发可以直接运行 CLI 或调用 `phone_texture.automatic.run`。正常执行无需补充人工材料，也不会进入对话等待。失败写入结果文件，整批不完整时不发布完整批次候选。

输出仍是交给用户验收的六面候选；程序不伪造视觉签收或当前 Blender UV 证据。历史 `start/run/approve-geometry` 是显式资料与签收流程，不能把它的 Agent 填表步骤混进无 Agent 自动路径。不锈钢高光生成流程另有依赖，不包含在本次铝材自动能力中。

本次修正的正确性回归与性能压测分开。修正后先检查十套顶面、保留其他面，再由用户确认是否启动新压测；不得复用旧版速度作为本版结果。

## 单侧相机凸起与偏置支架

标准版实拍中，支架可能占据原来采样的端部，较平的圆角也可能无法拟合指数曲线。原标定失败后，程序可从遮挡两侧分别读取裸露边框，用三个透明度阈值核对轮廓，再从原始照片测量接触处的 RGB 边缘。交替取列拟合和复测，接触区域的四段均需有边缘支持。仅在可定位的相机凸起、支架及各自交界处调整透明度。旋转前保留原图 RGB，旋转和精裁后复测机身与遮挡物的像素。

此路径适用于顶面自动标定，以及从原图运行边框标准化时的底面和侧面。原标定能生成结果时仍使用原算法。未找到两侧机身、存在竞争轮廓或中部凸起身份不明时，仍返回失败。边框候选生成后，贴纸、天线、按钮及材质继续执行各自的检查。

## 已确认的机型厚度模板（2026-11-23）

用户确认：上下线不一致时，统一机身横向宽度，以上沿平移固定厚度确定标准下沿。正常检测和已有接触区恢复均失败后，工坊按已选择机型启用此兜底。三款独立标定值如下。

| 机型 | 标准横向宽度 | 金属框名义厚度 | 已通过原图标定数量 |
| --- | --- | --- | --- |
| iPhone 17 | 988 px | 112 px | 106 |
| iPhone 17 Pro | 1000 px | 125 px | 108 |
| iPhone 17 Pro Max | 1080 px | 124 px | 107 |

top_body_profiles.json 保存同机型通过顶面原图检测的厚宽比中位数、采样范围和源文件指纹。输出另保留上下两行透明度覆盖边缘。正常输入继续走原处理，保持已有输出一致。

模板先以上沿和标准厚度预测下沿，在两侧露出的金属框区间用原照片的暗金属到背景交界独立测量实际下沿。每半边至少 70% 有支持，源图拟合残差限值仍为 2.5 px。相机和支架先在原坐标中排除，再将实拍上下沿确定性映射为标准的两条平行线。纵向源取样与模板的比例限于 0.85–1.15。真实端头继续沿用源透明度，镜头和整个相机台阶排除单独核验。

流程通过 frame_geometry 的 model 参数进入；模型未知时继续返回明确失败。源图测量、模板指纹、下沿原图支持率、变换、输出尺寸分别记入几何记录。
