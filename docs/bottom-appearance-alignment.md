# Optional bottom appearance alignment

This isolated candidate adds bottom alignment after geometry trimming and before any lighting masks, material analysis or structure-source bindings. Its goal is a visually centered port and natural hardware placement; it does not claim calibrated dimensions or model UV acceptance.

`phone-texture auto ... --bottom-alignment appearance` enables the stage (the isolated candidate default). `--bottom-alignment off` is the reproducible control. Existing task tuples without the new tenth field use appearance mode. The current host CLI still supports Pro/Max only; the separate standard-model sample validates the bottom stage and real lighting, not an invented standard-model seam profile.

The stage creates `work/bottom-alignment/selected` and leaves the six geometry input PNGs and original report untouched. The bottom may be resampled; five companions are copied byte for byte. An effective geometry record binds the selected PNG hash and records its pre-alignment hash. Both the ordinary downstream path and the host's source-preservation fallback receive this effective record. Masks, lighting jobs, frozen landmarks, and later source checks are computed from selected files, not earlier masks or coordinates.

States are `applied_with_notice`, `unchanged`, `kept_source_with_notice`, and `disabled`. Measurement uncertainty is never a failure of six-face generation by itself. A rejected correction preserves the input bottom PNG exactly and clearly reports that bottom alignment was not applied. There are no SKU-specific accept lists. Pro10 and Max50 follow the same path as every other sample; old research delivery holds are not imported.

The geometric estimator still uses model-specific hole positions and independent port/screw checks. It does not force a port to the canvas center. It refuses unsupported transformations rather than guessing an invisible edge. A separate validation layer checks finite, monotone in-bounds sampling, unchanged canvas, exact endcap pixels, bounded local stretch and outline movement. A damaged candidate is not saved as the selected bottom. I/O failure or unreadable inputs remain genuine errors.

Port position (2026-11-06): the whole port outline is hit with a rounded rectangle (template match on clipped, signed gradient, then continuous refinement) instead of per-row left/right edge tracks. A quality sticker beside the port is a single straight edge and cannot match the top, bottom and both rounded ends, so it no longer pulls the port centre. Paper covering the port itself shortens the visible outline; the independent hole holdout then rejects the correction and the input is kept.

Dark colours (2026-11-06): when holes cannot be read at three consecutive darkness levels, holes are re-read once on darkness relative to the nearby metal (median background with paper/highlights swapped out, in local noise units), with ring-shaped holes filled and 5-level steps. Holes still need three agreeing levels; the screw is confirmed from the largest agreeing group of readings and must still pass the 2.5 px holdout. Light colours never use this path. Replay of 28 distinct real bottoms: every previously corrected bottom is pixel-identical except one now within the 2.5 px no-edit tolerance; seven previously rejected bottoms are corrected with port holdout ≤1.4 px; one off-axis Pro Max sample stays rejected.

Pro Max (2026-11-09): the corner ratio is refined with the outline. Pro Max ports show a dark opening inside a lighter chamfer rim; a sticker against the rim can pull a fit into a mixed inner/outer outline. When the two seed fits disagree by more than 2 px, the opening itself is also fitted and fits whose two ends both show an edge (≥0.5) are preferred. Because holes alone drive the correction, the spread between port fits is recorded but no longer rejects; the 2.5 px port holdout remains the independent check. A dark port that separates from dark metal at only one darkness level also triggers the local-contrast retry. 61 real Pro Max bottoms: 59 corrected or already centred (previously-accepted 55 pixel-identical), 2 kept (blurred screw; port holdout); the 20 Pro bottoms are pixel-identical.

Center and contour numbers are diagnostics, not a replacement for visual acceptance. Illumination can change RGB after the geometric stage; only its alpha and canvas should remain the same as selected geometry. “Exact endcaps” concerns the geometry stage, not later approved lighting/color operations.

The integration replay reuses the same 11 frozen geometry groups and calls the same `finish_geometry` continuation as the production entry point. It does not rerun segmentation. Control and appearance modes run serially under `/tmp/phone-texture-global-processing.lock`, with one CPU/OpenCV thread and nice 19. A host antenna/effect fallback is reported separately from the bottom alignment decision. Original geometry files, original photos, current services and other tasks are not modified.
