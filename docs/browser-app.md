# 六面工坊 0.2.0

双击启动时会短暂打开终端窗口，完成后可关闭；后台服务继续运行。右上角「退出服务」可结束空闲服务。

运行 `phone-texture web --home /你的工具文件夹`，或双击本机交付目录中的「六面工坊.app」。浏览器仅访问 127.0.0.1，图片不上传。调用同一个 `phone-texture auto`，无需 Agent、生成模型或在线服务。依赖完整仓库、Python 环境、已安装 BiRefNet_dynamic 权重和 `psutil`（`pip install -e '.[cutout,browser]'`）。打包的本机启动器复用当前仓库环境，不是可直接复制到任意机器的独立安装包。

1. 选择单台原图文件夹，或含多个 SKU 的父文件夹；也支持粘贴路径。每台需六张原图，文件名可任意；导入时按图像检查六面方向及命名。名称不匹配时点击「是否一键命名」，核对缩略图后生成 front/back/left/right/top/bottom 命名副本，自动切换到副本继续处理。原文件名和内容不变。子文件夹只扫描一层；预览版每批最多选择 100 台。
2. 自动读取后勾选要处理的 SKU，设置 1–8 并发和独立保存目录。默认 5 台源自本机此前十台批次测量；不是所有机器、所有批次的保证。超过 4 台通过原 CLI 的显式实验并发能力执行。推理槽位固定 min(实际并发, 2)。10 并发因未完成验证暂不开放。
3. 开始后可看逐台步骤、已生成数、当前内存和本批耗时。刷新或关闭网页不影响任务。停止会结束整批进程组，保留记录。「继续未完成步骤」创建新批次，校验当前输入与本 SKU 几何检查点后复用抠图结果，重新计算后续步骤；没有完整检查点的项目从原图处理。不会覆盖旧批次，也不复用其他 SKU 的蒙版或标记。
4. 六面齐全计入「已生成」，同时分别显示调光、天线对齐和接缝是否完成。四个阶段都完成即显示绿色「已生成」，效果类偏差收在「查看处理提示」里，不要求复核；只有阶段未完成的候选显示橙色。背面统一输出为机型标准尺寸（17 Pro 1000×2080、17 Pro Max 1080×2254），并把镜头校准到标准位置，叠图与 3D 预览时摄像头稳定。未完成阶段的候选也可预览，并列出具体待核对原因。下载只包含实际导出且六面格式、哈希均校验通过的候选；部分批次与预警批次附处理说明，图片缺失或哈希不符时拒绝生成 ZIP。所有结果仍待用户视觉验收；固定模型的程序接缝检查不代表实际模型 UV 已验收。

当前适用本项目 iPhone 17 铝材标准拍摄规范；不锈钢与其他拍摄规范不可直接套用。用户应检查机型、方向、材料与最终裁切效果；识别不确定、疑似镜像侧面、重复方向、缺图或多图会阻止该 SKU 处理，不按排除法补全方向。

## 文件组织

导出目录仅保存「批次/SKU/六面 PNG」，每批独立目录避免覆盖。过程、日志、总览与下载 ZIP 保存在工具目录的「运行记录/批次」，任务索引保存在「任务记录」。网页仍可查看总览、下载 ZIP 和打开日志。历史批次保持原有路径与内容；重试沿用原导出位置，按新规则生成独立批次。

双击启动器优先重开本目录已有服务，否则由系统分配空闲端口，避免与其他本地工具冲突。同一目录持有排他锁，只允许一个服务；同一服务仅运行一个批次。浏览器页面通过随机令牌保护写操作，拒绝跨来源请求、未知 Host 和任意文件下载路径。

macOS 内存压力达到严重等级、交换空间较开始增加超过 8 GiB、可用内存不足 1 GiB 时自动停止；监测不可用时不绕过保护继续运行。运行时限为 max(900 秒, SKU 数 × 300 秒)。上述是保护阈值，不是硬件容量结论。原图重新检查并按原处理流程做快照和哈希校验；不会覆盖原图，也不覆盖旧批次。

网页刷新恢复进度来自服务端和落盘记录。正常关闭服务会停止运行中批次；重启后原有未结束记录标注「服务中断」，不会自动重用其工作区。系统睡眠会影响耗时，处理期间请保持机器唤醒。

验证：`python -m pytest tests/test_web_app.py -q` 覆盖输入缺失/重复/损坏、并发限制、目录重叠、进程组停止、服务中断恢复、跨站请求及导出完整性。全库回归 `python scripts/test_all.py`。

阶段与下载回归还覆盖旧版完整效果预警不误标天线未对齐、已对齐但接缝未完成的候选、未知逐面阶段、续接选择与新旧批次隔离、预警候选 ZIP 内容/哈希以及缺图或说明不一致的拒绝。界面按 `stage_status` 和 `per_face_stages` 展示；旧报告依据实际结构记录和完整处理状态兼容。空 `face_processing` 不等于“仅优化光照”。

原图与导出文件夹均可直接选择；任务明细、历史批次和说明默认收起；路径粘贴后自动读取，异常项单独提示，不再重复展示处理规则。


## 自动命名范围与验证

方向识别完全本地程序化，无 Agent、在线 API 或生成模型。冻结的 `iphone17-studio-views-v1` 参考库仅含 SKU_01–06 原图的多尺度边缘描述；不用输入文件名、SKU 编号、旧蒙版、几何标定或处理结果。粗轮廓区分正背/顶底；侧面以较细的按钮和天线边缘结构比对，并比较镜像候选。相似度不是概率。此方案依赖当前相机视角、构图和机型，不能作为任意手机/任意拍摄照片的通用分类器，也不承诺识别所有镜像或异常情况。

`recognition_data/atlas.json` 记录参考照片哈希、版本及阈值。参考变更需显式运行 `scripts/build_view_atlas.py` 并重新验证；导入用户图片不会训练或更新参考库。

`regression_view_recognition.py` 验证已提供的十台 60 张原图（参考 SKU 测试时排除自身），另外验证未入库 Pro Max 6 张，以及 20 张镜像侧面、6 张旋转图、1 张空白图的拒绝。另测匿名乱序文件、错误方向名称、重复图、复制字节一致性与检查后文件变化。该样本结果不代表新机型或不同摄影条件的准确率。

命名副本在工具目录 `命名副本/批次/SKU/`；同批 `命名记录.json` 记录来源、去向、哈希和识别证据。六面必须分别被可靠识别且各一张才可命名。未识别 SKU 不复制，界面保留跳过名单。复制前后及开始处理前重验图片哈希，变更则要求重新扫描。重复确认同一扫描不会反复生成副本。


## 2026-10-22 正面上边框误识别修复

Pro Max 的透明软边出现比真实金属/玻璃交界更强的 RGB 梯度峰，旧算法误取该峰，将上边框估为 2 px，后续有效材质支撑距离 80.02 px 超过原门限 48.825 px。现仅接受采样直边上至少 80% 像素 alpha≥240 的交界候选，排除透明软边假峰；原距离门限及光照 supported_field 检查均未放宽。新上边框估计 11 px，支撑距离 4.12 px。无机型名称分支、历史蒙版或手工点位。

该 Pro Max 从原图重新推理并完成六面、光照与结构处理。十套 iPhone 17 Pro 同样重新全流程处理，60 张最终 PNG 与既有 workers-4 验证结果逐字节一致，原图哈希不变。两个新增回归覆盖软透明边的强假峰及缺少不透明支撑必须拒绝；旧算法不能通过新软边回归。全库 307 项测试通过。证据位于项目 `outputs/front-rim-support-fix-20261022/`；图片仍需用户最终效果及真实模型 UV 验收。

原图与导出位置通过 macOS 系统文件夹选择器（NSOpenPanel）选择，可创建文件夹，取消保留当前路径。2026-10-22 按用户要求接入，未执行交互验证，待用户验收。

## 2026-10-22：型号与内收 UV 接缝

开始前选择 Pro / Pro Max；每批同型号。程序在结构对齐后自动匹配对应固定模型的四角接缝颜色，校正与质检均进入批处理，不依赖 Agent。默认不猜型号，旧记录仍可查看；重试旧批次须补选型号。实现与限制见 [固定模型边框 UV 接缝校色](frame-uv-color.md)。

天线使用用户明确选择的精裁后图片高度比例，由每台自己的背板建立目标，不以型号 UV 代替图片基准。程序排除极淡半透明拖尾，在调光前冻结天线标记，保留圆角和贴纸，并在最终导出前再次检查画布。无需 Agent 看图或补点；失败会返回具体阶段，旧批次需重新处理才能应用新规则。
