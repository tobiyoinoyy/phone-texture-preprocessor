# 侧面贴图尺寸统一与按钮对齐

本页记录兼容算法。整合后的批次处理使用 [统一入口](../README.md) 和 [场景标定规则](calibration.md)，下方底层命令仅用于历史复现。

处理已裁切的 left / right 贴图。分为尺寸统一和按钮位置映射两步；原图不覆盖。

## 准备

需要 Python 3、Pillow、NumPy：`python3 -m pip install Pillow numpy`。

输入文件夹内每个 SKU 一个子目录，包含 `left.png`、`right.png`。支持 PNG、JPEG、WebP、TIFF；同侧只能有一个文件。所有输入应为同一结构机型、相同朝向，已完成裁切。基准目录默认名为 `sku0`，可用 `--reference` 修改。

在脚本所在目录运行：

```bash
python3 -m texture_alignment.align_textures prepare '/实际批次目录' --output '/新的输出目录' --reference sku0
```

默认以 sku0/left 的高度作为所有图片共同高度。left 和 right 分别按 sku0 对应侧的宽高比确定固定宽度；同一侧所有 SKU 尺寸完全相同。使用 `--height 2048` 可指定高度，使用 `--width 128` 可同时指定两侧统一宽度。

此阶段将已裁切画面直接缩放到目标尺寸，不增加透明边距、不二次裁切。宽高比不同的源图会发生横纵独立缩放，这是统一模板尺寸的处理；如果源图含不同的空白边距，应先处理裁切一致性。

## 标记按钮

打开输出目录中的 `标注按钮.html`，选择 left 或 right，先标 sku0，再标其他 SKU。按从上到下的顺序点击对应按钮的上沿和下沿。各 SKU 同一侧必须标记相同数量、相同含义的点；两侧可以不同。

标记使用尺寸统一后的像素坐标，从 0 开始。顶部 0 和底部 H−1 自动固定，无需标记。页面横向放大便于点击，纵向保持原始像素；点选线附近可删除。标记页全部在本地运行，刷新前须导出保存。导出文件一般保存到浏览器下载目录。

导出的 `landmarks.json` 可通过“载入标记”继续编辑。也可直接编辑 JSON 中每个 SKU 的有序 y 坐标数组。

## 应用映射

```bash
python3 -m texture_alignment.align_textures apply '/新的输出目录' --landmarks '/已导出的/landmarks.json'
```

生成 `aligned/SKU名称/left.png` 和 `right.png`，以及前后对比图、所用标记与映射报告。结果目录已存在时会拒绝覆盖，可通过 `--output '/另一新目录'` 输出下一版。

同一 SKU 原有的 `front`、`back`、`top`、`bottom` 图片会原文件复制到结果目录，尺寸和像素内容不变，因此原批次包含六面时，结果文件夹也保留完整六面。仅对 left/right 做尺寸统一和按钮映射。

映射采用纵向分段线性插值：源按钮边界移动到 sku0 的对应高度，两端固定，区段之间连续。宽度不变，横向像素列不移动；输出高度始终等于第一步的统一高度。只有目标与源坐标完全相同且没有逐列斜率时，基准图才逐像素不变。透明度与颜色同步插值，并处理透明边缘，避免黑边。

这里“高度不变”指输出画布行数不变，不是每行内容不动；按钮归位必然使局部区段拉伸或压缩。算法不生成新瑕疵，但重采样可能改变细小瑕疵形状或锐度。

本脚本解决纵向位置错位；不估算真实三维姿态，不修复缺失表面，也不自动识别按钮。按钮点必须来自实际图片；不能跨不同机型或不同朝向复用。报告的 `segment_stretch` 是每段目标长度/源长度，接近 1 表示变形较小，异常大或小应优先检查点选。

## 验证

```bash
python3 -m unittest discover -s tests -p 'test_align_textures.py' -v
```

覆盖固定高度、按钮边界位置、首尾行固定、恒等映射逐像素不变、透明插值、非法标记拦截、整批输出与源图不变。


## 背板与模型 UV 接缝基准（v3）

按钮可沿用基准 SKU；天线必须单独确定对应背板的上、下边界。读取实际模型的材质及 UV，确认侧面接背板图片的哪一边，再按同一空间位置换算纹理坐标。不能凭 left/right 文件名推断图片左右。

配置 `targets_by_sku[SKU][side]` 的有序目标点，与 `points[SKU][side]` 一一对应；该字段存在时缺失任何 SKU/side 都报错，不回退到 SKU_01。旧 `targets` 仅兼容明确要求侧面共同参考的任务。模型和背板通过 `reference_files: [{"path": "基准文件绝对路径", "sha256": "实测哈希"}]` 锁定。

`seam_targets.transfer_row` 接收背板与侧面各自完整的 `[世界纵向坐标, v]` 接缝曲线。两条曲线必须位于同一世界坐标系、对应同一实际接缝，包含各自全部节点；不能只取位置恰好相同的共有顶点，T 接点和独立分段也必须参与。曲线非单调、坐标重复或越界时拒绝处理。函数不会自动识别 GLB 拓扑，曲线提取仍需按当前模型核查。像素中心换算采用 `v=(y+0.5)/H`。

`antenna_slopes` 与源定位点一一对应；按钮斜率通常为零。迭代修正天线时，添加中央结构区的保形锚点，使原有按钮、卡槽及局部颜色修复不受影响。从标准化源图一次重采样，不反复变形旧成品。

历史 v2 使用 SKU_01 左侧天线公共高度，只验证侧面之间一致性，不能据此宣称 3D 接缝正确；用于 3D 时应重新标定。历史批次辅助脚本现在要求 `--antenna-targets`（格式 `SKU -> side -> 四条天线边界`），不再内置目标高度。

校验尺寸、首尾、完整结构区像素、未修改四面文件哈希；逐处查看背板标定、同视角模型接缝。坐标换算不能消除原有材质色差与摄影反光，位置衔接和颜色衔接应分开判断。
