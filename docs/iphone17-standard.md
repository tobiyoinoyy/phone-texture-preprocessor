# 标准版 iPhone 17：当前实拍处理

`phone-texture auto 输入六面目录 --model iphone17 --work 独立过程 --output 新交付目录 --single-name sku1 --jobs 1`

此路线针对 2026-11-04 的标准版玻璃背板样本新增，目前验证范围是一组六面实拍和独立合成负例，不宣称任意标准版照片均适用。仅接受已经映射好 front/back/left/right/top/bottom 的单组六面目录；原图只读。过程目录保存自动候选，`processed_needs_visual_review` 不代表视觉或 UV 已验收；`output` 路径在独立复核发布前不创建。

分割使用同库 BiRefNet_dynamic，正背面 1536，其余 1024。几何复用同库的原图 RGB/alpha 交叉验证、四面刚性摆正、局部去支架、圆角与顶面排除相机门禁。几何/材料/结构资料均从当前原图测量，无手工逐 SKU 坐标输入。开发重算可复用绑定源哈希的本轮分割蒙版；新过程从原图推理。

标准版玻璃背板不运行 Pro 金属背板分区，也不捏造背板天线。窄金属圈由四边源图过渡测量；玻璃、屏幕、镜头不进入金属校色。只保护当前真实贴纸，底部纸尾用两侧边界消失与跨纸宽 RGB 下缘联合测量，不套 Pro 红色定位点的版式。按钮的完整闭合轮廓和暗沟/表面分别估计照明，不把检测矩形作为校色蒙版。原尺寸、alpha、纸面与材料域外像素在光照阶段逐像素锁定。

左右侧天线以本机背面**最外侧窄金属边上的真实天线断口**为基准。玻璃内区没有天线不等于背面图没有天线。程序沿本次几何图的外轮廓，在三个独立内缩采样轨迹上检测明亮断口的上下边界；缺失、竞争候选或轨迹不一致即拒绝，不能退回侧面自身比例。背面图左边对应 right（电源/相机控制），右边对应 left（音量/SIM）。按精裁后像素中心高度比例把背面实测四边界换算到对应侧面，目标横向平直。侧面原图独立检测只用于源坐标，不决定目标。结构重映射后验证两端与中央四边界，完整按钮区和圆角字节不变；软边 alpha 可随源像素重映射，不得丢失不透明机身。2026-11-04 首版仅拉平侧面而未读取背面断口的结果无效，修订版显式拒绝旧结构配置。

## 2026-11-04：right 底部残余偏差与用户确认的规则

用户在再次指出 right 底部偏差后，明确选择“仍分别使用背面左右两边的基准”。此要求优先于把两侧拉到同一高度的建议：

- **right → 背面图左边，left → 背面图右边**。上下天线都分别量取各自两条边界及宽度。背面两边本来有高差时保留；禁止平均、共用一边、复制另一侧目标、为了总览看齐而调整。配置与发布记录必须保存侧面名、实际背面边、背面源哈希和 `reference_policy: corresponding_rear_edge`。
- 不再直接用合并轨迹的整数梯度峰作为最终边界。本例右下对应背面左下原粗读数为 1831/1845，而三个独立轨迹的亚像素中位数为约 1830.343/1844.556。每批重新从自己的原图几何基线测量，**不把本例坐标或固定上移量写成模板**。
- 精裁后画布按像素中心比例换算：`side_y = (back_y + 0.5) / back_height * side_height - 0.5`。保留小数到采样阶段。复核排版必须用相同画布显示高度和顶部位置，明确标出对应背面边，不能拿不同缩放的截图直接量像素，也不能只对比 left 与 right 是否等高。
- **验收最终 PNG，而非仅验目标数组**：天线上下边界分别在侧面两端和中央重新检测，换回背面像素单位。标准版路线被修正的天线各边误差须 ≤ 0.6 px，宽度误差 ≤ 0.8 px；上下天线独立验收。目标正确但输出残差超限、只验中央或只验上天线均不能发布。必要的采样相位修正只从原光照基线重算，限幅并再次检查；不得移动背面目标来通过检查。
- **只修底部时锁住其他部分**：从绑定哈希的原光照基线重算底部映射；对照上次交付逐像素验证上部天线、完整按钮/卡槽、圆角及其余五张图片不变。发布器必须核对基线报告、锁定范围和实际 PNG，不能仅相信说明文字。
- 实看对应背面边和 right 下部的原尺寸、4 倍深浅背景图，记录两端、两边界及宽度。数值通过不替代用户验收，也不表示当前模型 UV 已验收。

实现为 `iphone17_structure.gradient_peak/rear_antennas/apply/refine_lower/validate_render_checks`；回归覆盖背面两边不同高度、共用错误一侧必须拒绝、亚像素读数、上部正确但底部仍偏及宽度错误。原图自动路线与局部修复都使用同一实现。

## 按钮：独立背面基准与透视缩放

2026-11-04 用户指出左右按钮未对齐，并要求“尽量用透视缩放的方式去移动，因为拍摄角度是有倾斜的”。本次明确同意相机控制键保持原位，只校准左侧三颗凸起按钮和右侧电源键；SIM 卡槽同样保持原位。不能将“天线变换期间按钮像素没变”当作“按钮位置已校准”。

`iphone17_buttons` 在当前 SKU 未调光的背面轮廓中独立识别按钮凸起：left 对背面右边三处，right 对背面左边电源键。使用三条透明度等值轮廓、按钮前后裸露边框的局部基线及金属 RGB 支持；缺少按钮、边界歧义、错误对应关系都拒绝。目标是本次拟合凸起深度 25% 的轮廓肩部，两端及中心均登记，不把本样本坐标写死。背面看不到相机控制键时不能猜测其位置。

左侧六个端点共同拟合纵向透视主变换，横向采样随投影分母缩放；少量端点残差用平滑插值校正。右侧只有一颗可可靠定位的按钮、两个端点，不能唯一确定完整透视参数，采用透视变换的仿射缩放特例。两者均从原像素一次采样，不是剪下按钮逐颗平移，也不宣称恢复了完整三维相机参数。源映射必须单调、不越界，并限制局部拉伸。

局部透视区域平滑衔接到已锁定的外边框、天线、相机控制键和卡槽；alpha 逐像素不变。逐颗检查最终 PNG 的上下端、中心、长度、完整闭合轮廓、原有划痕和间隙，不能只检查按钮总数或中心。数值误差是相对上述照片可测轮廓的采样误差，不代表物理边界零误差。原尺寸及每颗按钮 4 倍前后对比均须实际查看。独立发布 `publish_revision` 会重算变换并核验其他四面、锁定区域和图片哈希；成品仍只输出六张 PNG。

完整 `auto --model iphone17` 已接入“天线 → 按钮透视”阶段，保存单独的 `button_alignment` 检查。当前实拍与合成的已知透视样本均须回归；本次交付使用局部修订，以保留此前已验收的天线 PNG 像素。

底面基于 Apple iPhone 17 官方尺寸图 Sheet 1 的八个不对称孔位（3/5）拟合平面投影，充电口、可见螺丝和留出的两个孔位独立验算。孔位、留出孔、端口及螺丝任一超限即失败。输出只做有源像素支持的内部登记，固定两端圆角，不采用 Pro 的完整曲面外推，不生成不可见表面。此方法是底面图片空间对齐，不是完整机身三维度量校正。标准版图纸：https://developer.apple.com/download/files/accessories/dimensional-drawings/iphone-17.pdf

几何、材料、结构和端口程序全部成功后，实际检查六面的原尺寸/4 倍图、源图叠加、四角、整条接触边、贴纸纸边、天线两端与完整按钮。`phone_texture.iphone17.publish(work, review, output)` 验证源、候选及证据哈希和逐面真实复核记录后，才创建只含六张 PNG 的交付目录。自动入口不伪造 reviewer 或勾选视觉签收。输出不含模型接缝验收，也不使用 Pro/Pro Max 固定 UV 接缝配置。

## 2026-11-11：并入 0.2.0 时的几何与天线锁定

标准版并入 0.2.0 后，0.2.0 为 Pro/Pro Max 新增的三项共享改动会改变本样本的已验收结果（背面贴纸底边出现台阶、左右侧各少 1 列、天线源坐标端部改变），因此标准版路线显式关闭：

- `frame_geometry(..., separate_support_edge=False)`：侧面支架接触下沿仍保留原 1px 外扩；
- `plate_geometry(..., reconstruct_paper_tail=False)` 与 `paper_mask(..., source_tail=False)`：背面不用 Pro 印字尾部重建；
- `iphone17_structure.per_column_boundaries`：保留标准版验收时的逐列天线追踪，不用 Pro 的 `antenna_material.trace_boundaries`。

三个开关默认值不变，Pro/Pro Max 路线不受影响。验证：同一组 11-04 实拍在 0.1.1 与 0.2.0 上分别运行，六张成品逐字节一致，结构、按钮、光照检查记录一致。以后要让标准版采用上述 Pro 改进，须先在标准版实拍上单独视觉复核。
