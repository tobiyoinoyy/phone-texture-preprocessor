# 手机六面质检图处理

接收六张照片、一个六面文件夹或包含多个 SKU 的目录，输出每 SKU 的 `front/back/left/right/top/bottom.png`。默认保留实拍色调和可辨损伤，原图只读，过程与成品分开。不自动加载进模型、不自动推送 Git。

## 先确定本次输入

沿用用户已给的型号、材质、范围及验收要求。缺少面名时先查看图片建立映射；左右不明时询问，不能猜。试验 3–4 组只处理所选组。原始横向边框照片与已经摆正的透明贴图区别处理；原图入口的左右面会旋转 90°，不能重复执行。

先读 [运行与安装](references/run.md)，从本仓库相邻目录读取以下 Skill 的 SKILL.md：
- `phone-texture-preprocessor`：确定性抠图、精裁、摆正；必需。
- `phone-aluminum-frame-restore`：铝金属保留源色、减弱缓变明暗。
- `phone-six-view-restore`：不锈钢仅修复确认高光，需要内置图像编辑工具。

三者均随仓库提供，优先读取仓库内版本；缺少文件时修复完整安装，不回退到个人目录旧版，也不替换为其他分割或生成算法。灯光依赖不可用时明确记录该阶段未执行，不能将“只完成裁切”称为全流程完成。材质决定处理方法；无法可靠确定时先问材质，仍可继续几何处理。混合材料按区域分流，屏幕、玻璃、镜头不能跟随金属整面校色。

## 执行

1. **建独立工作区并确定交付目标。** 模型贴图任务保持 intake 默认 `model_textures`，必须完成结构对齐。只有用户明确只要照片处理时才用 `photos` 并记录范围理由；不得因检测失败改目标。 用 `scripts/workspace.py intake` 登记选中 SKU、原始路径和哈希，并复制到统一输入结构。未知文件名先在工作区映射副本，保留原文件来源，不重命名原图。
2. **几何标准化。** 按预处理 Skill 运行 `standardize`；已裁图按需要 `deskew`，已验收图片直接复制。自动边缘检查失败时查看原图及遮挡，使用绑定原图哈希的轮廓、局部去支架蒙版和角度标定；不放宽阈值。六面均按[几何复核门禁](../../docs/geometry-review.md)检查：原图叠加、四角、完整下缘和接触区的原尺寸/4×深浅背景图；有歧义、启发式去支架、人工标定及外推边缘时增加独立机身/支架检查，旋转前后及精裁后都合格再 `approve-geometry`。矩形不能代替局部去支架；保护 back 纸尾。标准化已摆正就不再 deskew。
3. **冻结几何基线。** 用 `workspace.py checkpoint --geometry-report 几何过程/report.json` 登记已通过几何复核的六面 PNG。缺少该报告或仍需复核就不能冻结；光照像素约束合格不能替代几何合格。后续光照阶段的尺寸、alpha、坐标和保护验证都相对此基线，不能拿未裁原图的尺寸比较。建立光照蒙版之前先检查六面轮廓、支架残留、裁边及方向。
4. **登记范围，再做光照。** 按[整圈金属验收](references/perimeter-review.md)先运行 `workspace.py lighting-scope` 冻结逐面目标。六面铝材处理须检查 front/back 的可见金属边缘，不能把“保护屏幕”解释为“整张 front 复制”；有整圈去黑边目标时两面登记 `perimeter`，不能用 `regional` 轻度提亮代替。确实不在用户范围内的面按依据登记 copy；不能在结果不达标后降级。 铝金属先读依赖的 `references/material-harmonization.md`，使用 `harmonize_aluminum.py`，默认 `source_lightness`。逐面查看实际图片，登记材料域、稳定参考框、保护与拟合排除范围；按钮金属用自身样本单独拟合，不能把边框场外推进按钮或降低 `supported_field` 门槛。按用户最新保护要求登记。本项目用户已要求“只保护贴纸”：必须采用 `protection_policy: sticker_only`，protected_mask 仅含当前原图真实纸面（无贴纸则空），天线、按钮、边缘与开孔不能再设像素冻结带。不同材质各自估计光照，不等于统一涂成金属色；源图真实损伤与结构仍保留。不可借 editable_mask、零权重或旧粗蒙版变相冻结已要求处理的位置。不锈钢按其 Skill 建确认高光蒙版、生成候选、限定范围合成，无确认高光的面按字节复制。**没有一个通用参数或亮度阈值能自动完成材料分类。** 蒙版与参考坐标只用于已核对的当前图片，不能复用其他 SKU 的位置。任何用户已明确取消的保护遵从本轮授权。
5. **验收光照候选。** `perimeter` 必须独立检查四边、四角、同材料色调、纸边与材质交界，生成同坐标原尺寸/4×深浅背景对照并填真实复核记录；发布器同时核对冻结范围、金属可编辑覆盖、源图绑定的效果样点和成品绑定的复核证据。像素约束与去黑边效果分别记录，缺项或不合格不得发布。 填写逐面处理清单，最终 `workspace.py publish` 还要经过下一步结构门禁；此时不能把光照候选当成模型贴图成品。先看原尺寸及局部放大对照，重点看整颗按钮、按钮间隙、天线端点、划痕和纸边；校验通过不等于视觉合格。发现新增色块、晕圈或细节丢失，修正材料域/场/参数后从几何基线重算，不模糊成品掩盖问题。成品只含六面 PNG，所有脚本、蒙版、报告、检查图另存。含贴纸的处理面必须按[贴纸边界规则](references/run.md#贴纸保护边界防止纸外出现黑色矩形)登记真实纸轮廓与纸外金属检查区；发布前同时验证纸面受到保护、纸外金属没有被误冻结，并查看左右及底端近景。

6. **结构对齐与最终发布（模型贴图必做）。** 按[结构发布门禁](references/structure-delivery.md)从本次光照候选运行 `align-structure`，复核后给 `publish` 传入 `--structure-process` 和 `--structure-review`。缺少结构过程、任一侧/任一天线检查，或使用旧记录时拒绝发布。使用当前 SKU 自己的背板作为基准，不能用其他 SKU 天线位置。iPhone 17 系列可选 `front_back_images`，将各 SKU 正背面机身轮廓与天线四条边界作为左右侧参考，前后两端不一致时按侧面宽度分别衔接。按钮按独立基准锚定，不从天线猜按钮位置。模型 UV 已有缩放/平移时选 `model_uv` 换算实际接缝。新裁切图不能套历史标记。需要模型接缝验收时通过 Blender MCP 检查当前工程并备份，记录实际 UV/图片指纹；无场景证据时只交付图片处理结果，不宣称 3D 无缝。结构重映射会改变像素坐标，应另建阶段记录，不把它送入要求 alpha 不变的光照验收。

## 交付

生成一张总览：所有 left 放一起、right 放一起、top 与 bottom 各自一起；front/back 同样保留。细节对照放过程目录。简短给出成品路径、实际处理面、检查结论和必要的残留问题。光照优化用于减少拍摄影响，不能称作恢复被高光遮住的真实瑕疵或物理固有色。

已被用户指出的暗斑必须逐项加入 `local_checks`：天线四端、按钮根部、边框局部；每项保存源图坐标、材质依据及原尺寸/4倍证据。全边中位数不能替代小区域暗部检查。

局部修复也执行 `local_checks` 与 `local_review`，不只对 perimeter 面生效。每次交付说明实际修复的面；沿用的侧面不能因为背板通过检查而视为已解决同类端点问题。左右侧上下天线的两端与相邻金属分别检查，位置、宽度不随光照处理改变。
