# 手机六面质检图处理

接收六张照片、一个六面文件夹或包含多个 SKU 的目录，输出每 SKU 的 `front/back/left/right/top/bottom.png`。默认保留实拍色调和可辨损伤，原图只读，过程与成品分开。不自动加载进模型、不自动推送 Git。

无 Agent 运行以 `phone-texture auto` 为入口：本采集规范的六面分析与处理均由程序执行，不能依赖 Agent 看图补点、画蒙版或填签收。失败明确返回，不降低标准。用户最终验收独立于程序运行。顶面必须排除整个摄像头台阶及镜头，仅保留顶边框本体；原图、旋转后、精裁后均检查。算法、适用范围和旧标定拒绝规则见 [顶面本体标定](../../docs/top-body-calibration.md)。

## 本项目本轮已确认的纯程序处理要求

用户已取消旧AI生图安全区及纸边像素保护。当前自动入口默认 `--protection-policy none --review-fallback preserve-source --lighting-profile accepted-shadow-lift-v1`：无纸边末端阻断；纸面仍按自身材质拟合并保持印刷可辨，天线证据与机身边界检查单独保留。以下历史说明中的 `sticker_only` 仅适用于用户另外明确要求保护纸面的任务，不能覆盖这项最新要求。

已认可的加强提亮效果仅覆盖 Pro SKU14、SKU34 的交付图；其他SKU不因此视作外观或当前模型UV通过。局部提亮目标预警保留原失败值，并允许候选继续后续阶段；源图、alpha、拟合支持等硬检查仍执行。原位待审不等于结构对齐。详见 [加强提亮候选](../../docs/accepted-shadow-profile.md)。

## 统一入口与默认基准

标准版 iPhone 17 玻璃背板照片使用独立的 `--model iphone17` 路线；当前范围、底部不对称孔位/充电口对齐和独立复核发布见 [标准版处理](../../docs/iphone17-standard.md)。不能套用 Pro 金属背板或固定 UV 接缝规则，也不能把侧面投影坐标写成背板天线实测。

2026-11-04 用户再次确认：标准版 `right` 天线以背面图**左边**为准，`left` 以背面图**右边**为准，上下分别独立量取；保留背面两边真实高差，禁止改成共用一边或平均位置。必须使用亚像素读数并复测最终 PNG 的两端、中央、上下边界和宽度；只修底部时其余五面及该侧上部/按钮/圆角逐像素锁定。具体发布阈值与本例回归见上述标准版文档，不能仅凭目标坐标一致宣布对齐。

标准版按钮另行按本机背面凸起位置校准，不能把“未被天线变换移动”当作按钮已对齐。用户要求优先透视缩放：左侧三按钮共同拟合，右侧电源键按可识别两端缩放；本例相机控制键经用户确认保持原位。锁住天线与外轮廓，逐颗核对上下端、长度及4倍近景，详见标准版文档的按钮规则。

本项目命名完整、采集方向及印字质检纸符合已验证规范的 iPhone 17 铝材照片，可用 `phone-texture auto 原图目录 --model iphone17pro --jobs 2` 从原图生成六面候选。该入口重新推理分割并分析当前轮廓、贴纸/材料、背面与侧面天线和按钮；无历史蒙版或标定输入。自动提案与数值检查不会填写视觉签收，完整候选仍须下述几何、材料边界、纸外金属和模型适配复核。其他材质/拍摄规范继续使用正式配置流程，不默认套用自动采集规范。

新任务使用 `phone-texture start 输入 --work 过程 --output 成品 --material aluminum` 建批，然后 `phone-texture run 过程` 续接；用 `phone-texture status 过程` 读取实际待办。桌面“一键处理”使用同一程序。完整配置、两种材质的任务格式与固定模型复核见 [统一运行流程](../../docs/workflow.md)，不要另写一次性编排脚本。

默认 `alignment_basis: back_image`：左右侧面上下天线使用当前待处理 SKU 自己的 back，不能借其他 SKU 的背面或天线目标。按钮保持独立标定。仅在本轮明确选用正背面两端约束时建批指定 `front_back_images`；不能因标定失败自动切换。六面图仍归属于当前 SPU/SKU，不跨设备拼图。

固定 UV 模型任务在建批时关联 `--model-reference`。发布会额外核对六面固定坐标、镜头、按钮、接口与平直天线。此门禁只验证已配准图片；不执行自动语义配准，不把每 SKU 自身背面对齐当作固定模型适配。实际配准不合格应回到几何阶段新建版本；不随 SKU 改模型 UV。

## 先确定本次输入

沿用用户已给的型号、材质、范围及验收要求。缺少面名时先查看图片建立映射；左右不明时询问，不能猜。试验 3–4 组只处理所选组。原始横向边框照片与已经摆正的透明贴图区别处理；原图入口的左右面会旋转 90°，不能重复执行。

先读 [运行与安装](references/run.md)，从本仓库相邻目录读取以下 Skill 的 SKILL.md：
- `phone-texture-preprocessor`：确定性抠图、精裁、摆正；必需。
- `phone-aluminum-frame-restore`：铝金属保留源色、减弱缓变明暗。
- `phone-six-view-restore`：不锈钢仅修复确认高光，需要内置图像编辑工具。

三者均随仓库提供，优先读取仓库内版本；缺少文件时修复完整安装，不回退到个人目录旧版，也不替换为其他分割或生成算法。灯光依赖不可用时明确记录该阶段未执行，不能将“只完成裁切”称为全流程完成。材质决定处理方法；无法可靠确定时先问材质，仍可继续几何处理。混合材料按区域分流，屏幕、玻璃、镜头不能跟随金属整面校色。

## 执行

1. **建独立工作区并确定交付目标。** 模型贴图任务保持 intake 默认 `model_textures`，必须完成结构对齐。只有用户明确只要照片处理时才用 `photos` 并记录范围理由；不得因检测失败改目标。 用 `phone-texture intake` 登记选中 SKU、原始路径和哈希，并复制到统一输入结构。未知文件名先在工作区映射副本，保留原文件来源，不重命名原图。
2. **几何标准化。** 按预处理 Skill 运行 `standardize`；已裁图按需要 `deskew`，已验收图片直接复制。自动边缘检查失败时查看原图及遮挡，使用绑定原图哈希的轮廓、局部去支架蒙版和角度标定；不放宽阈值。六面均按[几何复核门禁](../../docs/geometry-review.md)检查：原图叠加、四角、完整下缘和接触区的原尺寸/4×深浅背景图；有歧义、启发式去支架、人工标定及外推边缘时增加独立机身/支架检查，旋转前后及精裁后都合格再 `approve-geometry`。矩形不能代替局部去支架；保护 back 纸尾。标准化已摆正就不再 deskew。
3. **冻结几何基线。** 用 `phone-texture checkpoint --geometry-report 几何过程/report.json` 登记已通过几何复核的六面 PNG。缺少该报告或仍需复核就不能冻结；光照像素约束合格不能替代几何合格。后续光照阶段的尺寸、alpha、坐标和保护验证都相对此基线，不能拿未裁原图的尺寸比较。建立光照蒙版之前先检查六面轮廓、支架残留、裁边及方向。
4. **登记范围，再做光照。** 按[整圈金属验收](references/perimeter-review.md)先运行 `phone-texture lighting-scope` 冻结逐面目标。六面铝材处理须检查 front/back 的可见金属边缘，不能把“保护屏幕”解释为“整张 front 复制”；有整圈去黑边目标时两面登记 `perimeter`，不能用 `regional` 轻度提亮代替。确实不在用户范围内的面按依据登记 copy；不能在结果不达标后降级。 铝金属先读依赖的 `references/material-harmonization.md`，使用 `harmonize_aluminum.py`，默认 `source_lightness`。逐面查看实际图片，登记材料域、稳定参考框、保护与拟合排除范围；按钮金属用自身样本单独拟合，不能把边框场外推进按钮或降低 `supported_field` 门槛。按用户最新保护要求登记。本项目用户已要求“只保护贴纸”：必须采用 `protection_policy: sticker_only`，protected_mask 仅含当前原图真实纸面（无贴纸则空），天线、按钮、边缘与开孔不能再设像素冻结带。不同材质各自估计光照，不等于统一涂成金属色；源图真实损伤与结构仍保留。不可借 editable_mask、零权重或旧粗蒙版变相冻结已要求处理的位置。不锈钢按其 Skill 建确认高光蒙版、生成候选、限定范围合成，无确认高光的面按字节复制。**没有一个通用参数或亮度阈值能自动完成材料分类。** 蒙版与参考坐标只用于已核对的当前图片，不能复用其他 SKU 的位置。任何用户已明确取消的保护遵从本轮授权。
5. **验收光照候选。** `perimeter` 必须独立检查四边、四角、同材料色调、纸边与材质交界，生成同坐标原尺寸/4×深浅背景对照并填真实复核记录；发布器同时核对冻结范围、金属可编辑覆盖、源图绑定的效果样点和成品绑定的复核证据。像素约束与去黑边效果分别记录，缺项或不合格不得发布。 填写逐面处理清单，最终 `phone-texture publish` 还要经过下一步结构门禁；此时不能把光照候选当成模型贴图成品。先看原尺寸及局部放大对照，重点看整颗按钮、按钮间隙、天线端点、划痕和纸边；校验通过不等于视觉合格。发现新增色块、晕圈或细节丢失，修正材料域/场/参数后从几何基线重算，不模糊成品掩盖问题。成品只含六面 PNG，所有脚本、蒙版、报告、检查图另存。含贴纸的处理面必须按[贴纸边界规则](references/run.md#贴纸保护边界防止纸外出现黑色矩形)登记真实纸轮廓与纸外金属检查区；发布前同时验证纸面受到保护、纸外金属没有被误冻结，并查看左右及底端近景。

6. **结构对齐与最终发布（模型贴图必做）。** 按[结构发布门禁](references/structure-delivery.md)从本次光照候选运行 `phone-texture align-structure`，复核后给 `publish` 传入 `--structure-process` 和 `--structure-review`。缺少结构过程、任一侧/任一天线检查，或使用旧记录时拒绝发布。默认使用当前 SKU 自己的背板作为基准，不能用其他 SKU 天线位置。iPhone 17 系列可选 `front_back_images`，将各 SKU 正背面机身轮廓与天线四条边界作为左右侧参考，前后两端不一致时按侧面宽度分别衔接。按钮按独立基准锚定，不从天线猜按钮位置。模型 UV 已有缩放/平移时选 `model_uv` 换算实际接缝。新裁切图不能套历史标记。需要模型接缝验收时通过 Blender MCP 检查当前工程并备份，记录实际 UV/图片指纹；无场景证据时只交付图片处理结果，不宣称 3D 无缝。结构重映射会改变像素坐标，应另建阶段记录，不把它送入要求 alpha 不变的光照验收。

## 交付

生成一张总览：所有 left 放一起、right 放一起、top 与 bottom 各自一起；front/back 同样保留。细节对照放过程目录。简短给出成品路径、实际处理面、检查结论和必要的残留问题。光照优化用于减少拍摄影响，不能称作恢复被高光遮住的真实瑕疵或物理固有色。

已被用户指出的暗斑必须逐项加入 `local_checks`：天线四端、按钮根部、边框局部；每项保存源图坐标、材质依据及原尺寸/4倍证据。全边中位数不能替代小区域暗部检查。

局部修复也执行 `local_checks` 与 `local_review`，不只对 perimeter 面生效。每次交付说明实际修复的面；沿用的侧面不能因为背板通过检查而视为已解决同类端点问题。左右侧上下天线的两端与相邻金属分别检查，位置、宽度不随光照处理改变。
